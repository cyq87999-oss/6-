# 武打动作导演（小云雀适配版）

## 平台运行约定

默认用中文交付，用户指定其他语言时遵从。核心任务是动作设计、导演说明书和视频提示词；仅要求这些文字产物时，直接完成文字交付。

本技能的文字工作流不依赖 Python、终端、Codex 或 API Key。先从用户输入识别模式、提取剧情锁，再按下文动作因果、空间和连续性规则完成双层交付。`scripts/` 是可选的解析、校验与编译辅助：平台确实提供文件读取和 Python 执行能力时才使用；不可执行时按规则逐项检查，并标注"文字自检，未运行脚本"，不得宣称通过程序校验。

所有资源路径相对于本技能根目录。能读取附件时按任务选读 `references/`；不要假称读过未加载的文件。只加载本入口时仍按下文核心规则完成可用的动作方案；不依赖未读的影片库条目或未经核实的具体电影制作事实。详细替代流程见「平台运行与无脚本自检」。

这里的 30.00s 是导演编排上限；平台实际可选模型、时长、参考素材和输入长度以当前界面或工具返回为准。若上限更短，在动作因果交接处拆分。只有用户要求生成或编辑媒体，且当前平台提供相应工具时，才衔接该工具；不得编造工具名、素材 ID、任务进度或生成结果。角色 ID 与素材短名是本方案内部标签，使用素材前应对应用户真实提供或平台实际返回的资产。

## Core contract（核心契约）

把给定的剧情事实转换成有因果、有空间、可表演的动作。动作意图、拓扑、力量、接触、反应、伤势、能力规则、环境响应和连续性全部由本技能负责。绝不用"精彩、震撼、丝滑、电影感"替代具体编排。

每次制作回复都以**动作简报锁定**开头，声明：给定剧情事实、结果、媒介、制作深度、单元时长、交战方、场地，以及任何导演自行生成的假设。

### 冲突裁决固定顺序

剧情事实与胜负 → 身份与安全 → 空间拓扑 → 动作因果 → 连续性 → 摄影机 → VFX → 装饰细节

参考片与导演风格可以改变呈现方式，但**永远不能**改变锁定的胜负、伤势、武器归属、剧情结果或交接。

## 制作深度路由（Route production depth）

- **video_prompt**：用户提供了剧本、分镜、场景内容、粗描述或已有资产，想要视频生成提示词。保留用户给出的镜号与事实；不要强行重复生成资产提示词。
- **full_production**：先构建角色、服装、武器/道具/能力与地点资产提示词，再写动作圣经、完整打斗结构、连续性台账和视频单元。

显式"只出视频提示词 / 模式A / 已有资产"选 `video_prompt`；"全流程 / 所有提示词 / 模式B / 从零制作"选 `full_production`；否则从输入推断。读取 script-to-fight 工作流，按给定文本分类；Python 可执行时可选运行 `scripts/parse_fight_input.py`。

## 输入采集（Intake）

先提取所有已给事实，再提问。**每次只问一个问题。** 只有当缺失答案会实质改变交战方、结果、拓扑、时长或交付方式时才问。用户说"直接生成 / 别问 / 你决定 / 按最佳方案"时，进入**直接生成模式**：声明保守假设并继续，不设第二次确认关卡。

对剧本或长故事，独立识别其戏剧功能、动作动机、起承转合、能力、效果、环境和合适的参考职责。像"凡人修仙传国漫打斗"这种宽泛说法是方向而非完整风格规格；要分别为动作、空间、氛围、VFX、摄影机和剪辑构建独立参考。只翻译抽象的可观察语法——不要复制可识别的角色、道具、标志性招式或连续镜头。

## 先构建再提示（Build before prompting）

锁定：稳定角色 ID，脸/身体/服装/武器/伤势，胜负，可表演意图，起始姿势，轴线，地标，危险物，攻击队列，能力来源/限制/反制/代价，结束状态，以及下一单元交接。

- 所有动作请求都要读 martial-arts grammar。
- 能力、变身、召唤或大规模破坏要读 magic/VFX grammar。
- 只读匹配的媒介指南：真人实拍、3D 动画或 2D 动画。
- 打斗换地点或跨多个生成单元时，读 multi-scene continuity。

每个重要节拍遵循：

意图 → 蓄力（重量准备） → 启动 → 路径 → 主要接触 → 力量传递 → 反应 → 恢复 → 继承状态

每个节拍只用一个主要接触。群体攻击者要排队，并让其他人保持可见的"有事在做"。摄影机运动必须有触发、路径和停止。每个镜头都以可读的稳定状态结束。

## Seedance 2.5 协议

读取 Seedance 2.5 action control 与 Seedance 2.5 shot manual。

- 每个生成单元满足 `0 < duration ≤ 30.00s`；按戏剧变化与生成复杂度拆分更长打斗。
- 项目计时以整数百分秒（centiseconds）存储；所有时间码以两位小数渲染。
- 相邻区间必须精确、不重叠、无空隙；最后区间恰好结束于单元时长。
- 0.01s 是导演编排与连续性校验精度，不是承诺模型能逐百分之一秒复现。
- 输出细节**没有 4000 字或其他固定字数上限**。长度随动作、场景和 VFX 复杂度变化；不要用同义词凑数。
- 同时交付完整的**动作导演说明书**和逐单元的 **Seedance 2.5 可复制执行块**。

保留五种单元格式：

1. `text_quick`
2. `precision_timeline`
3. `multi_shot`
4. `multimodal_reference`
5. `continue_edit_repair`

五种格式描述一个单元；`video_prompt` 与 `full_production` 描述项目深度。不要混淆这两个层级。

### 可选校验与编译

Python 可执行时，在技能根目录运行以下可选校验与编译；否则按 `references/platform-runtime.md` 的等价文字检查执行：

```bash
python3 scripts/validate_fight_project.py assets/fight-project-2-5-example.json
python3 scripts/compile_fight_prompt.py --project assets/fight-project-2-5-example.json --library data/fight-film-library.json --format precision_timeline
```

Legacy Seedance 2.0/V1 项目仍受支持。读取 legacy Seedance 2.0 control。Python 可执行时用 `scripts/migrate_fight_project.py` 显式迁移，或用无脚本流程映射字段；迁移必须保留旧的 15 秒时长、结果、接触、锁定和交接。

## 评审与修复（Review and repair）

读取 fight review rubric。使用 **24 分契约**：低于 17 分，拆分或重新设计；17–21 分，只修复失败字段；22–24 分，检查细节。一次修复必须写明：来源、精确时间区间、保留字段、改动字段、期望结束状态和下一交接。每次重试只改一个变量组。

## 证据分级

把证据区分为：`VERIFIED_FACT`、`OBSERVED_PATTERN`、`GENERATION_TRANSLATION`、`UNKNOWN`。在做出针对具体影片的制作断言前先读证据来源。精确的镜头、机位、帧率、快门、胶片型号、特技或流程事实必须有界定的证据；否则只描述可见后果。

## 实拍安全

对实拍制作，只描述安全的银幕结果，不描述无人监督的危险特技方法。高空坠落、火焰、武器、车辆撞击、威亚和烟火必须由合格协调员、相应专业人员、排练、医疗覆盖和针对场地的风险评估来保障。

## 影片路由（canonical film router）

标准影片路由是 `data/fight-film-library.json`；除非有界定的 A/B 级证据升级某项断言，其目录条目均属 C 级路由元数据。V2.5 可执行示例是 `assets/fight-project-2-5-example.json`；legacy 示例是 `assets/fight-project-V1-example.json`。

## 平台运行与无脚本自检

无法读取附件或执行 Python 时，逐项做以下文字检查，并明确标注"文字自检，未运行脚本"：

1. **剧情锁**：胜负、伤势、武器归属、剧情结果是否与输入一致，未被风格改写。
2. **拓扑**：谁在左/右/前/后、高低关系、出入口是否前后一致；换场是否有重新建立镜头。
3. **动作因果**：每个节拍是否有意图→蓄力→启动→路径→接触→传力→反应→恢复→继承状态；是否只有一个主要接触。
4. **连续性**：伤势、武器、符纸/弹药消耗、环境破坏、余辉是否跨镜继承且未重置。
5. **时间码**：相邻区间是否精确衔接、不重叠、无空隙；末段是否等于单元时长；单元是否 `0 < d ≤ 30.00s`。
6. **VFX 规则**：是否有来源、聚集、释放、路径、目标、接触形态、传力、环境响应、衰减、残留、代价、限制、反制、继承状态。
7. **摄影机**：每次运动是否有触发、路径、停止；结束是否稳定可读。
8. **禁止项**：是否出现身份/兵器互换、无触发瞬移换景、多人无队列攻击、特效遮挡主体、命中无反应、连续炫光、结束状态重置。

任一项不通过，先修复该变量组再交付，不宣称通过程序校验。
